**Why it matters**
Named example of the psychosis-thread failure mode: when agents produce a *working* port quickly, skipping verification scaffolding (Miri, type-challenges-grade suites) inherits *none* of the safety story of the destination language. Read with δ-mem / agent-memory papers as the research counterweight — capability up, discipline lagging.

### 7. δ-mem: Efficient Online Memory for Large Language Models

- **Points**: 226
- **Comments**: 58
- **URL**: https://arxiv.org/abs/2605.12357
- **HN**: https://news.ycombinator.com/item?id=48158506

**Summary**
Research on compressing past context into a **fixed-size state matrix** updated by delta-rule learning — HN splits between "elegant compression" and "doesn't solve real memory / caching."

**Key discussion**

- Practitioners want papers to report **RAM bytes to load/run** alongside param counts — FP16 4B ≠ INT4 4B; MoE headline params mislead when memory is the constraint.
- Skeptics: fixed-size state doesn't solve associating compressed memory with queries (activation sensitivity); doesn't improve semantic caching; fundamental information limits remain.
- Optimists: fixed-size state + "journal" of past tokens + learned retrieval → agents with bounded GPU footprint and long-horizon memory; directly addresses "re-feed 4 markdown files every session" pain.
- Open questions: training cost, legitimate vs. overfit compression, production cost absent from paper skim.

**Why it matters**
Connects to the week's X/agent thread on persistent memory and repo guidelines without token burn. Even if δ-mem isn't the winner, the comment thread shows demand for **standardized memory-footprint reporting** and bounded-state agents — eval and product specs should include bytes, not just params.
